FAQ

Why two hours?

The starter line is there so you can use Vola right away, before your own server is ready. It's a starting allowance, not the product: Vola is built around the server you run, and everything else keeps working after the starter line closes.

The two hours count from the first time you open Vola, whether or not you're connected. They can't be extended or earned, and there's nothing to buy.

What happens at closing time?

  • The starter line stops working and is removed from this iPhone. Its saved password is deleted.
  • Your own lines, auto-join rules, proof runs and the logbook keep working.
  • If Vola isn't open at closing time, the starter line closes the next time you open it. Until then it disconnects whenever this iPhone sleeps.
  • If you turned on "Hand over when the starter line closes" and your line's last proof passed, Vola switches to that line when the starter line closes. If Vola isn't open then, this happens the next time you open it.
  • Moving this iPhone's clock back doesn't add time. Moving it forward closes the starter line early, and that can't be undone.
  • Reinstalling Vola doesn't restart the two hours, because iOS usually keeps the saved start time.

What do I need for my own line?

  • A server iOS can connect to natively with username and password (EAP) sign-in, such as strongSwan. OpenVPN, WireGuard and L2TP servers are not supported.
  • A certificate iPhone already trusts. The server proves who it is with a certificate from a public certificate authority, such as Let's Encrypt. Vola can't install certificates, so a server with a self-signed certificate won't connect.
  • A name for the server. Use a domain name that points to the server and is included in its certificate; the Remote ID is that same name. No domain? The Vola setup script uses a free sslip.io name, which always points to your server's address.
  • Open ports. Allow UDP 500 and UDP 4500 in your provider's firewall and on the server (and ESP, IP protocol 50, if your provider filters it).
  • Forwarding. Turn on IP forwarding and NAT on the server, so traffic can leave it. Without them the line connects, but your exit address doesn't change.
  • A username and password for each person who uses the server.

The setup script does all of this on an Ubuntu cloud server you control. Build your own line walks you through it.

Is it safe to share a line with its password?

Anyone who gets a line with its password can use your server, and their traffic goes out through your server. Share it only with people you trust, and give each person their own user so you can remove one without affecting the others.

A line shared without its password contains the server address and username. Whoever uses it needs the password from you.

Vola can't take back a line you've shared. To stop someone using your server, delete or reset their user on the server: sudo vola-server user del <name>, or sudo vola-server user add <name> --reset for a new password.

Why doesn't Vola show data usage?

iOS doesn't give personal VPN apps the number of bytes sent and received, so Vola doesn't show it rather than make it up. The logbook shows what Vola can know: when each session started and ended, how long it lasted and why it ended.

A strongSwan example

If you set up a server by hand instead of with the setup script, this is the shape of a minimal strongSwan configuration (/etc/swanctl/conf.d/home.conf) that VolaVPN can connect to. It is an example: every value is a placeholder, so adjust it to your server.

connections {
  home {
    version = 2
    remote_addrs = %any
    pools = home-pool
    send_cert = always
    local {
      auth = pubkey
      certs = vpn.example.com.pem
      id = vpn.example.com
    }
    remote {
      auth = eap-mschapv2
      eap_id = %any
    }
    children {
      home {
        local_ts = 0.0.0.0/0
      }
    }
  }
}

pools {
  home-pool {
    addrs = 10.10.10.0/24
    dns = 1.1.1.1
  }
}

secrets {
  eap-alice {
    id = alice
    secret = "choose-a-long-password"
  }
}
  • The certificate goes in /etc/swanctl/x509/, its private key in /etc/swanctl/private/ and the issuer's intermediate certificate in /etc/swanctl/x509ca/. Load everything with sudo swanctl --load-all.
  • In VolaVPN, the server address and the Remote ID are both vpn.example.com, the name in the certificate. The username is alice.
  • Allow UDP 500 and UDP 4500 in, and turn on IP forwarding and NAT for 10.10.10.0/24.

The line format

A line's QR code, the link you paste and the link the setup script prints are the same text, format vola-line/1:

volavpn://line?v=1&name=Home&host=vpn.example.org&rid=vpn.example.org&user=alice
KeyRequiredMeaningLimits
vYesFormat version, 1Whole number
hostYesServer addressA domain name (lowercase, labels of 1–63 letters, digits or hyphens, at least two labels, up to 253 characters) or a dotted IPv4 address. Non-ASCII domains in punycode.
ridNoRemote IDUp to 253 printable ASCII characters, no spaces. Missing or empty means the same line's host.
userYesUsername1–64 characters, no control characters
nameNoLine nameMissing means the host. On import, names longer than 32 characters are shortened and a repeated name gets “ 2”, “ 3”…
pwNoPassword — only in a line shared with its password1–128 characters, no control characters. Empty means missing.
  • Two kinds only: without a password (no pw key, the default) and with one. There is no “verified” field: every imported line gets its own proof run before VolaVPN calls it proven.
  • Encoding: UTF-8, and every value is percent-encoded except the unreserved characters A–Z a–z 0–9 - . _ ~. VolaVPN writes the keys in the order v, name, host, rid, user, pw and reads them in any order. Key names are lowercase.
  • Size: at most 1024 bytes. QR codes use error correction level M.
  • Versions: a line with v greater than 1 asks you to update VolaVPN. Unknown keys are ignored; a key that appears twice makes the line invalid.
  • Pasting: leading and trailing spaces are ignored, and a single volavpn://line? link inside other text (for example, copied with a terminal prompt) is found. Text with two links is rejected.
  • Older setup script output: VolaVPN also reads the {"format":"vola-server/1", …} line printed by setup script 1.0.x (server address, Remote ID and username; no password).
